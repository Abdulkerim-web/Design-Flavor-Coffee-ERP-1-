==================================================
1. PRIMARY OBJECTIVE
==================================================

Create the complete Inventory experience for the ERP.

The inventory interface must make it immediately obvious:

- what inventory exists
- where it exists
- what is physically on hand
- what is reserved
- what is actually available
- which inventory requires attention
- which lots exist
- where a lot came from
- what movements affected a lot
- whether stock is healthy
- whether stock is approaching a warning level
- whether stock is insufficient
- whether a discrepancy requires review

The inventory experience must support the three primary inventory categories:

1. Green Coffee
2. Roasted Coffee
3. Packaging Materials

The same conceptual inventory pattern must be used across all three.

66. FINAL PRINCIPLE
==================================================

The inventory module must make stock trustworthy.

A user must never have to guess:

how much physically exists,
how much is reserved,
how much is available,
which lot contains it,
why the quantity changed,
or whether a stock problem requires action.

Use a consistent three-way inventory model:

ON HAND
RESERVED
AVAILABLE

Use the same visual language for:

green coffee,
roasted coffee,
packaging.

Make lot history auditable.

Make shortages obvious.

Make discrepancies actionable.

Keep operational information dense but understandable.

Most importantly:

THE FRONTEND DOES NOT CALCULATE INVENTORY.

THE FRONTEND VISUALIZES AUTHORITATIVE INVENTORY DATA.

Build the entire Inventory experience as a polished, enterprise-grade operational workspace while preserving the established Coffee-Roasting ERP design system, CSS architecture, responsive behavior, dark mode, accessibility, reusable components, and RBAC-aware UX.
